# Automatic head detection and tracking validation

## Question and trigger

Can the released gaze checkpoint process a continuous video without supplied head boxes, while preserving frames and recording stable local track IDs? The previous demo required a per-frame CSV; the user requested video-only input and GitHub synchronization.

## Design

Frozen flowET_d6 seed 0, epoch 14 checkpoint; existing 360-frame, 1280x720, 30 fps MLB Interview source MP4 (VideoAttentionTarget). SHA-256: 4449e8c49c28beb2bedaca94b8650c519c6fb0cfd1ca9330dca9b8f5fd821ea3. YuNet 2023mar CPU detector, threshold 0.8, maximum side 960, expanded face boxes and Kalman/Hungarian tracking. Default all-person inference; 10,000 flow samples per person/frame, Heun 16, gamma 3, seed 2026. No gaze annotations or head annotations in automatic mode. No retraining.

First run two-frame automatic and legacy-CSV smoke checks, plus two blank synthetic frames for the zero-detection path. Then run the complete 360-frame source. CPU unit tests cover reordered detections, short and long gaps, persistent target selection, scene reset, boundary clipping, and CSV validation.

## Preregistered acceptance criteria

- Every decoded frame produces one encoded frame, including zero-detection frames; complete source produces 360 frames / 12 seconds.
- All prediction arrays and head coordinates are finite; selected IDs agree between CSV and per-frame NPZ; all per-person hypothesis weights sum to one.
- No fabricated gaze outputs on the blank synthetic input; its empty per-frame arrays have valid shapes.
- Legacy supplied-box mode still runs with the same checkpoint.
- Visually inspect first/middle/final preview; boxes should match visible people, with separate colors/IDs and gaze targets. Record misses and fragmentation; do not infer tracking accuracy without identity ground truth.
- Full ffmpeg output decode succeeds. Any crash, frame loss, or non-finite output fails this implementation validation.

### Acceptance checks and visual observations

- No frame loss: all four runs passed decoded-frame count, duration, and full FFmpeg decode checks.
- Every saved prediction is finite. CSV and NPZ frame/track/box associations agree. All per-person hypothesis weights sum to one; empty arrays retain valid dimensions.
- The blank run preserves both frames with zero gaze predictions. The legacy CSV run retains one supplied head per frame and loads the released checkpoint successfully.
- First, middle and final previews (frames 0, 180, 359) were inspected. Head boxes cover the visible faces/heads, with matching local ID/gaze colors. The boy is initially facing away and is first detected at frame 16. There are no additional track IDs after ID 4 appears in this clip. No identity annotations were used, so this is not proof of zero ID switches.
- This real clip emitted no predicted-gap boxes and no scene resets. Gap handling, expiry, reset behavior and selector locking are covered by synthetic unit tests, not demonstrated by this video. All seven CPU unit tests passed locally and on the compute host.
- Additional I/O checks passed for odd-size output padding and a 90-degree rotated video. The first rotation fixture failed to carry rotation metadata; it was corrected using FFmpeg `-display_rotation 90` and passed without changing inference code. See `environment_and_review.json` and `io_checks.json`.

### Evidence boundaries

One short interview clip validates the pipeline, not detector recall, identity tracking accuracy, generalized gaze quality, or all possible codecs. Face-derived head boxes can miss back-of-head/profile/occluded views. Geometry-only IDs can change at crossings or long gaps. No retraining or paper metric evaluation was performed. Gaze remains unsmoothed; the tracker filters head geometry. The rendered movie displays each track's top hypothesis; all five hypotheses remain in the NPZ files.
